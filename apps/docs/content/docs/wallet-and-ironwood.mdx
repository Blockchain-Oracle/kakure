## Deposit from Ironwood

Since the NU6.3 upgrade (mainnet block 3,428,143), new shielded value on Zcash lives in the **Ironwood** pool; the
older Orchard pool can only be spent from. A payment that moves money from one pool to another shows its amount on
chain. So deposit from funds that are already in Ironwood: then your deposit is a same-pool shielded payment that
hides sender, recipient and amount.

**Zodl users:** Zodl 3.9.0 added migration into Ironwood. Migrate first, then deposit.

Pay the exact amount the deposit sheet shows, with its memo unchanged: the memo carries your deposit's id, and only
the id claims the chips. Payments with the same id add up; anything below the smallest chip (0.00001) can't be
minted.

## Where withdrawals go

A withdrawal pays out to the address you paste. It must:

- be a **Unified Address** (`u1…` on mainnet, `utest1…` on testnet) for the network you're on;
- contain an **Orchard receiver**, so the payout lands in the shielded pool;
- contain **no transparent receiver**, which would make the payout public.

The app checks all three in your browser, with the same rules the mint applies, before it sends anything.

Use a **fresh** address for each withdrawal (your wallet's Receive screen gives you a new one). The operator sees
where each withdrawal goes, so reusing one would link your withdrawals to each other: the mint refuses an address it
has paid before.

Withdrawals start at 0.01 and go in steps of 0.001. The house pays the network fees.
